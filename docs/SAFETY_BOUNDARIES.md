# EcomSRE-Agent Safety Boundaries

This document owns operational safety rules. Architectural rationale belongs in
[ARCHITECTURE.md](ARCHITECTURE.md); accepted choices are indexed by Decision ID
in [DECISIONS.md](DECISIONS.md).

This document provides the normative safety detail for `DEC-004`, `DEC-007`,
and `DEC-012`. `DEC-012` takes effect only in Phase 3 and does not authorize a
Phase 0 executor or write path.

## Authorization boundary

Planning, documentation, testing, review, or a green acceptance result does not
authorize commit, push, PR, merge, archive, release, deployment, training,
Docker execution, or later-phase work. Each protected action requires explicit
authorization.

## Phase 0 ownership boundary

Every mutable resource must have:

- the stable project namespace `ecomsre-phase0`;
- a project ownership label;
- a run or lifecycle reference where applicable;
- a matching entry in the ownership manifest.

Every Compose mount with `type: volume` must also resolve to an explicitly
declared, run-scoped named volume with matching project/run labels. Service
mounts may not create anonymous or undeclared volumes. Allowlisted `bind` and
`tmpfs` mounts follow separate path and leakage rules; unknown mount types fail
closed. A volume declaration or mount that cannot be mapped exactly before
mutation blocks startup.

The project may act only when all identifiers agree. Missing, conflicting, or
unreadable ownership information produces `RESOURCE_OWNERSHIP_UNKNOWN`.

Preflight fails closed on unknown containers, networks, volumes, port owners,
locks, files, or process metadata. It reports the exact conflict and a manual
diagnostic path; it does not take over or remove the resource.

## Permanent prohibitions

- global Docker cleanup, including `docker system prune`;
- stopping or deleting unknown containers, networks, or volumes;
- killing a process to free a port;
- changing host networking, security, or Docker settings;
- arbitrary shell generated by an LLM;
- mutation outside project-owned local Demo resources;
- real credentials, production systems, enterprise environments, or cloud
  resources;
- writes to public Internet services;
- silent upstream version, image, architecture, or engine fallback;
- deletion or rewriting of failed-run evidence.

## Upstream boundary

The OTel Demo submodule is read-only. Project wrappers may select frozen files,
provide environment overrides, add ownership metadata, and query APIs. They may
not patch upstream source to make the baseline pass. A reproducible upstream or
ARM64 failure is evidence for a new Decision Record, not permission to improvise.

## Evidence confidentiality and leakage

Observer-visible and evaluator-only artifacts use separate roots. The
observer-visible tree must not reveal feature-flag key/value, scenario name,
expected answer, evaluator label, or semantic filename/path/URI.

Future agent tools receive only observer-visible data. Recursive reads from a
common artifact root are forbidden. Evaluator-only data is available only to
the external scorer and scenario controller.

## Lifecycle and cleanup

- `reset` changes only the allowlisted scenario control and preserves evidence.
- `stop` targets only resources proven to belong to the active project.
- cleanup is a distinct, explicit action.
- a failed run is stopped safely when possible, then retained.
- if owned cleanup cannot be proven safe, terminate with
  `MANUAL_INTERVENTION_REQUIRED`.

No failure permits a broader cleanup command.

Stop authority is an authenticated capability over one exact Docker daemon and
one exact resource set. Observer-visible evidence persistence is not part of
that capability. If observer persistence fails after authentication, record the
failure without discarding the in-process capability long enough to attempt the
exact project-scoped stop. Direct `phase0-up` returns
`MANUAL_INTERVENTION_REQUIRED`; a supervised smoke records terminal `UNSAFE`.
Any daemon identity or resource-set drift invalidates the capability and fails
closed.

`down -v`, prune, and deletion by unverified historical IDs are prohibited.

## Evidence integrity lifecycle

Terminal evidence is sealed only after the final stop or scene-preservation
events are persisted. If a later necessary safety action extends an already
sealed failed run, the original report and seal remain immutable. Recovery uses
a versioned report, a versioned seal, and an append-only chained seal index.
Validation must cover the initial checksum, all prior recovery seals, and the
current audit trail. See
[PHASE_0_ACCEPTANCE.md](PHASE_0_ACCEPTANCE.md#evidence-layout) for the owned
layout.

## Phase 3 write model

The Planner emits a typed remediation plan; it never emits executable shell.
The deterministic Policy Gate checks target ownership, action type,
preconditions, blast radius, approval, mutation count, and rollback
availability.

An initial remediation attempt permits one forward mutation, such as one
allowlisted flag change, frozen configuration rollback, or specified replica
adjustment. Read-only checks, verification, and the compensating rollback do
not count as forward mutations. Rollback authority is reserved before the
forward action.

Human approval is required by default. Automatic approval is legal only in an
explicit local test mode with the same allowlist and ownership checks.

The attempt stops immediately when a precondition is false, a write partially
fails, verification times out, the business SLO does not recover, a regression
appears, rollback fails, or resource state becomes uncertain. It must not issue
a second forward mutation.

## Terminal safety states

| Marker | Meaning |
|---|---|
| `UNSAFE` | Requested or observed action violates policy |
| `MANUAL_INTERVENTION_REQUIRED` | Safe automatic continuation is unavailable |
| `ROLLBACK_FAILED` | Compensating action did not restore the required state |
| `STATE_UNKNOWN` | Current resource or business state cannot be established |
| `RESOURCE_OWNERSHIP_UNKNOWN` | Project ownership cannot be proven |

Any terminal safety state forbids another forward mutation. An LLM may explain
the state but may not expand authority.
