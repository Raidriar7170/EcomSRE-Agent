## 1. 研究问题与非目标

### 1.1 两个可检验的贡献

- **表示贡献：**操作分层、同口径参考对比和局部依赖分析，相对基础遥测输入是否提供了额外判别信息？

```text

        ↓

        ↓
```

### 4.1 最小数据契约

以下是语义要求，不强制开发同名类或新的 Product 协议版本：

- `AnalysisRequest`：工具名、真实目标 ID、窗口/参考句柄、分组粒度、展开粒度。
- `AnalysisResult`：分析 ID、目标/窗口、计算方法、结果表、来源引用、覆盖/截断、限制、底层访问成本。
- `ObservableQuestion`：一个可计算字段/关系及比较条件，条件在看到该次返回值之前确定。
- `Hypothesis`：稳定 ID、开放文本解释、目标范围、支持/冲突分析引用、预测和未解释部分。
- `InvestigationReport`：根因候选排序、局部解释、确认的观测事实、竞争解释、残差、下一观测建议。

原始 observation 与 `analysis_results` 分开放。分析引用应能追溯到实际输入，但分析结果不冒充连接器原始响应，不自动进入知识注册器。

保留可信元数据与不可信文字的区分。操作名/日志片段可作为数据进入模型，不可作为指令；只允许经过校验的字段与模板控制工具执行。

### 4.2 与旧循环解耦

新建 `investigate_semantic_v1`，不修改旧 `investigate` 的含义，不要求新调查通过资源预测才能结束。

实验标识使用 `(case_id, method, repeat)`；同一事故的重复运行不创建新的“独立事故”。复用已有传输和计算组件；仅在必要处做窄适配，不复制整个 Provider/Repository/Worker。

## 5. 工具一：`profile_operations`——操作级异常分解

### 5.1 接口与输入

建议能力：

```python
profile_operations(services, window, group_by, detail_level)
# group_by: operation / span_kind / purpose
# detail_level: summary / representative_records
```

服务、窗口和参考都来自真实输入目录或已验证参数。不要提供任意 SQL、PromQL、Python 或自由文件路径执行能力。

从保留原始响应或具备字段的连接器输入读取服务/实例、操作、span 类型、错误状态、起止时间、时延以及可用的 Trace/span/parent 身份。旧投影已经丢失且原始材料不存在的字段不得反推或编造。

### 5.2 语义分层

支持 `BUSINESS_REQUEST / BUSINESS_ASYNC / CONTROL_STREAM / UNCLASSIFIED`。映射依据实际操作和部署语义，不依据错误率、时延大小或是否能让结果更好看。

第一版允许冻结的人工语义映射；这是方法先验，不声称模型自动学会了用途分类。映射对 B/C/D 完全相同；A 也能访问同一元数据/映射说明，不制造字段可见性优势。

同一操作成功和失败归入同一用途组。控制流不等于无害；未分类不等于健康；异步风控不能因为不是同步 SERVER 请求就被排除出业务。

### 5.3 计算与返回

按同口径分组返回调用数、错误数、错误比例、可计算的时延特征、覆盖状态和代表记录句柄。

- 对计数器优先复用已有正确计算，不开发完整 PromQL 引擎。保留首尾差只称观察增量，不伪装成精确 rate。
- 错误分子/分母同来源、同维度、同时间支持；零分母返回不可计算。
- 完整兼容桶可聚合桶后计算分位数；不能平均组 p95，不能相减 p95。
- 只有部分桶时允许输出明确的桶超限比例，不补造完整 p95。
- Trace 样本分布和指标总体分布分别报告；不能把样本错误率当总体错误率。
- 不把同一 RPC 的 CLIENT/SERVER、消息 publish/receive/process 相加为独立订单。
- 展示 top-k 时保留其他组的数量、贡献与未覆盖提示；分母在裁剪前按实际可用范围计算。
- 缺失、NaN、reset、新标签、截断在相关维度局部处理，不把无关的可计算结果全部丢弃；也不以缺失补零。

**局部完成条件：**能指出观测异常集中在哪些操作组，并保留未分类/未知；不要求给出唯一根因或全系统健康结论。

## 6. 工具二：`compare_baseline`——同口径参考对比

建议能力：

```python
compare_baseline(scope, signal, window, reference_id)
# scope: service + operation/purpose + span kind/direction
```

参考句柄在当前事件之前固定。按服务/可比较实例范围、操作用途、方向、单位、统计方法和窗口定义匹配；整服务参考不能直接替代业务子集参考。

区分“历史参考”与“经独立确认的健康基线”。本轮允许仅研究相对历史变化，不要求为了使用参考再完成全系统健康资格认证。

第一版实现绝对差、相对变化、连续偏离点数；需要排序时可采用稳健标准化：

```text
z = (current - median(reference)) / max(1.4826 * MAD(reference), epsilon)
```

`epsilon`、所需参考数量和判别阈值按信号单位在开发配置中固定。MAD 为零、参考太少或单位不可比时输出限制/辅助差值，不靠任意极小 epsilon 制造巨大异常分数。

相对变化遇到零参考值不能直接除法；参考计算不能使用当前故障窗口。该分数是排序特征，不是根因概率。

参考不足正常返回 `INSUFFICIENT_REFERENCE`；可以继续其他工具。不得为补齐旧 live-03 基线启动新部署或回到完整采集验收。

**局部完成条件：**能对可比范围计算变化，不能比较的范围有明确原因，不从历史参考或零观察错误推导“已经确认健康”。

## 7. 工具三：`compare_dependencies`——局部依赖对比

建议能力：

```python
compare_dependencies(target, neighbors, window, signal)
```

第一版限于真实拓扑/Trace 支持的一跳关系，最多三个邻居。拓扑是结构背景；某窗口实际发生调用需要该窗口的观测，二者不混为一谈。

输出目标与邻居的相对变化、观察到的调用边、同 Trace 的错误分布、可比较的异常起点及其时间分辨率、父 span/采样缺失与限制。

- 不把最早异常、最大异常或 `first_error_location` 直接等同于根因。
- 不把服务名字、同时变化或静态连接关系当成唯一因果证明。
- 时间先后只有在时钟与采样分辨率支持时才比较；否则保留未知。
- 缺失 parent/Trace 身份时降级为有界关系摘要，不能编造图边。
- 资源、队列、Runtime、Changes 等独立异常继续保留为残差。

**局部完成条件：**能给出对竞争解释有用的局部关系比较；没有足够观测时明确指出不足，而不是硬选下游为根因。

## 8. 算法核心：对比式视图选择 D

### 8.1 假设与可观察预测

维持最多四个稳定 ID 的假设。解释可以开放生成，不限于既有故障 Catalog，也不给模型提供测试集机制答案枚举。

每个假设可提出一到两个可观察预测，例如：

```text
H1：业务处理退化
预测：业务操作自身相对匹配参考偏离。

H2：控制流影响服务级聚合
预测：已观察异常主要集中在控制流操作。

H3：下游依赖问题传播
预测：上游异常主要位于调用该下游的路径，且下游有相应变化。
```

它们不必互斥。某个观测预测成立不等于完整机制成立，多个问题可以共存。

可观察问题必须绑定可计算字段/关系与预先确定的比较规则。模型给出每个假设对同一问题的预期：`YES / NO / UNSPECIFIED`；实际结果为 `YES / NO / UNKNOWN`。不要看到答案后重写原预测以制造正确性。

### 8.2 每轮选择

模型提出少量合法候选分析，标明希望区分的解释；程序校验参数并按以下代理评分选择：

```text
S(a) = Q(a) * D(a) / (1 + C(a))
```

- `D(a)`：候选分析中，相同可观察问题上预期相反的有效假设对比例。`UNSPECIFIED` 不算相反；只有一个假设时允许按其关键预测缺口选读。
- `Q(a)`：根据当前已经可见的字段/参考/来源元数据判断的可执行程度；不得偷看该工具尚未返回的数据答案。
- `C(a)`：预计底层查询数、处理量或返回体量的归一化代理成本；开发阶段固定计算，不依赖测试标签。

称其为“判别价值代理”或“对比式启发策略”，不称为已校准的信息增益、因果发现或最优策略。第一版不训练权重、不增加评审 Agent；候选提出与选择可以在一次模型回复内完成，程序完成排序，所有调用计费。

若没有有效分歧，允许有限的探索性分析或补齐关键预测；不能为了提高分数强行创造互相矛盾的假设。成本相同的并列用稳定次序处理。

### 8.3 更新与停止

程序执行后，记录实际可观察结果；模型据此更新支持/冲突和假设排序。

进展定义为：一个新问题得到有效答案、某个既有预测首次获得支持/冲突，或关键缺口被确认为不可解决。可计算结果对解释的意义仍是模型推断，不升级为形式化因果验证。

不算进展：同一输入同一分析重复返回、只换假设措辞/ID、增加无新内容的记录、把 UNKNOWN 改写成“正常”。规范化分析参数用于去重；确认一次数据缺口后不反复计为进展。

连续两轮无语义进展、额度耗尽、没有有价值的可执行分析，或可输出边界明确的局部结论时结束。不要以“必须剩下一个假设”为停止条件。

### 8.4 最终研究输出

输出有序根因组件候选（可为空）、带范围的解释、计算事实、仍成立的替代解释、独立残差和下一观测需求。支持局部结论与拒答。

禁止直接输出知识晋升、恢复授权或“已确认全系统健康”。研究报告不改写原正式诊断。

## 9. 数据方案：优先多机制的小样本，而不是同一事故反复窗口化

### 9.1 数据目标与降级

规划目标为 12 个开发事件、24 个未用于调参的测试事件，覆盖至少四类机制或易混淆场景；这是研究规模目标，不是统计充分性保证，也不是已经拥有的数据量。

先用一张表确认实际存在的数据、字段、标签与独立事件数。优先现有真实回放；不足时检查 OpenRCA 等官方公开数据的一个合适子集。只选一个主要数据来源适配，不扩展为多数据集平台。

若现有材料不够且公共数据在授权/下载范围内不可用，完成已有材料上的实现、边界样例和有限真实实验，报告样本量不足。不能把 36 个事件当作必须通过新部署凑齐的条件。

大文件不绕过下载上限；许可不明确不下载/再发布。已知缺字段的数据集不凭空补 operation、父关系或基线。

### 9.2 两条评测轨道

| 轨道 | 输入与真值 | 用途 |
|---|---|---|
| 根因定位 | 有独立组件标签的事故；标明标签来源 | Acc@1 / MRR 等定位指标 |
| 语义判别 | 操作混合、无参考、部分 Trace 等有明确局部判据的材料 | 错误归因、未知处理与计算正确性 |

人工构造/遮挡样例标为合成或派生，单独报告；它们不增加真实独立事故分母，也不能自动证明某个根因在观测上不可识别。

live-03 已用于设计，属于开发/案例分析，不能重新命名成盲测；相邻窗口及重叠支持只算同一事件组。没有唯一根因真值时不纳入根因 Top-1。

### 9.3 只保留必要隔离

- 同一事故、重叠窗口、同一部署故障派生变体进入同一 split；重复模型运行不增加独立样本数。
- 输入文件名、目录名、case ID、故障开关及标签文件不能泄露根因；使用中性 case 句柄，保留正常服务身份和拓扑。
- 定义组件粒度、候选服务范围和评分规则后再看测试输出；所有组一致，不能把真根因偷偷缩进候选集合。
- 现有知识库和规则固定；不向任一组额外提供测试标签或基于测试结果生成的总结。
- 测试标签由评分程序读取，不进入模型可见内容；不让同一模型同时产生标签并证明自己正确。
- 依据字段可用性、标签可靠性等预先标准决定适用轨道；不能按结果好坏挑选测试事件。

一份输入清单和 split 文件足够，不新增数据资格证书、审批服务或冻结数据库。

### 9.4 时间与在线能力边界

每案固定相同可用数据快照，区分事件时间与资料采集/可用时间。允许做事后完整快照上的离线诊断，但必须标为 retrospective replay。

当时不可用、后来才补采的 Trace 可用于单独的事后分析，不用于声称在线调查提高。无法证明可用时刻的数据不假装满足在线 cutoff。

若同一事故同时做“当时可用”和“事后补充”对照，两者配对报告，不当成两个独立事故。第一版无需额外采集来证明在线能力。

## 10. 四组实验与公平性

| 方法 | 能力与策略 | 归因目标 |
|---|---|---|
| A：基础遥测＋普通 ReAct | 合法过滤、分页、基础读取；看到相同可用字段/参考元数据，不提供新的三类专用分析视图 | 表示/工具整体收益 |
| B：语义工具＋固定流程 | 三个相同工具；由开发集固定顺序与确定性对象选择 | 固定流程是否已经足够 |
| C：语义工具＋普通 ReAct | 三个相同工具；模型自由选择，不要求显式分歧矩阵与代理排序 | 同工具下的强基线 |
| D：语义工具＋对比式策略 | 第 8 节方法 | 决策策略的额外贡献 |

### 10.1 公平输入与预算

所有组采用相同模型、推理档位、候选服务、初始信息、可用数据边界、上下文/输出上限和底层访问上限。原历史实现可作附加对照，但不能故意沿用删字段输入作为唯一弱基线。

A 可以访问相同操作字段和用途映射说明，也可以分页；不得把完整有利信息只给 D。B/C/D 共用计算实现和语义映射，不按方法修改数据。

B 的流程和目标选择不读标签，不默认指定 fraud/payment/Kafka 为根因；C 允许正常自主推理，不人为禁止其提出假设。

必须同时记录分析动作数、模型请求数、token、底层查询数/读取量和计算成本。一次复合工具内部查询多个目标不能只记成一次免费读取。

无网络的回放也计等价数据访问量。允许缓存，但策略、预处理与成本归属保持一致；不能预先计算 D 的全量答案而让其他组付读取成本。

调用失败、格式失败、拒答保留在结果中；受预算影响未启动的轨迹标记未完成，不伪装成已执行错误。已启动且失败的根因案例按评分规则计为未正确定位。

### 10.2 执行顺序

先少量开发案例检查成本和功能，再做固定测试。方法运行按事件配对，采用预先确定的平衡/随机顺序，避免先把 D 跑完、剩余预算不足以跑对照。

目标：四组各完成一次固定测试；预算允许时 C/D 各追加一次完整重复。两次重复逐次报告及配对汇总，不挑最佳一次，不把重复当新事件。

开发阶段最多两轮策略/提示词语义修订；不要无限调参。测试前固定配置、主指标和收益目标；看过测试后不继续调好再冒充同一独立测试。

若预算不足，优先保留共同完整的 A/B/C/D 小规模配对集，按预先规则说明截断顺序及遗漏数量；完整测试状态仍为 partial。

## 11. 验收：任务完成与算法收益分开判定

### 11.1 交付完成条件

| 项目 | 必须实际做到 | 不要求 |
|---|---|---|
| 工具 | 三个工具实现；具备相应数据的案例上真实计算；缺数据局部返回限制 | 每份历史数据都字段齐全 |
| 模型循环 | 有真实模型选分析、读取返回、更新解释/停止的轨迹 | 每个案例都给肯定诊断 |
| 对照 | 固定输入、预算和评分规则下完成预定四组实验，保留失败 | 指标必须上涨 |
| 分析 | 有定位/语义判断/成本结果及逐案例差异 | 完整论文、线上延迟或生产证明 |
| 复现 | 一个入口、配置、数据清单、逐运行输出可对应；记录代码版本与模型配置 | 多套摘要证书或全仓库历史审计 |
| 隔离 | 原事实、规则、正式诊断和恢复权限不变 | 新规则注册与晋升 |

只有 fixture、只有代码或只有离线算术，不能标记“真实模型实验完成”。材料不足可以交付部分结果，但不能用全 UNKNOWN 或生成虚构指标代替执行。

### 11.2 主指标与错误断言

默认主指标：

```text
Acc@1 = 首选根因组件正确的事件数 / 固定根因定位测试事件数
```

组件粒度、允许答案和并列规则提前固定；不能结果出来后把实例粒度降成服务粒度以抬分。拒答、已执行的 Provider/格式失败按未正确定位计，不能从分母删掉。

辅助报告 MRR 或 Acc@3 中一个，以及以下两类指标：

- **错误断言：**在预先标注的局部证据不足/冲突案例上，是否仍明确宣称“根因已确认”“业务故障已排除”“全系统健康”。同时报告回答覆盖率，防止全拒答获得好看的错误率。
- **成本：**全部模型输入/输出 token（包含实际计费的 reasoning，依 Provider 可见口径说明）、真实/预留费用、底层访问量和分析量；不只统计成功调用。

事实数值由程序核验，解释范围按固定 rubric 人工核对或盲化方法名检查。LLM judge 可以辅助，不作为唯一真值或唯一成功门槛。

“工具调用非空”“schema 合法率”“假设数量减少”仅为调试指标，不是算法贡献。

### 11.3 预设收益目标

这些是本轮设计目标，不是已有成绩，不是通用行业标准。

默认选择**质量目标**：

```text
D 相对 A：Acc@1 至少增加 10 个百分点。
D 相对 C：Acc@1 至少增加 5 个百分点。
D 在配对语义判别集上的错误肯定结论不多于 C，并同时报告覆盖率。
全部结果在共同预算上限内解释，实际成本增加必须明示。
```

24 个根因测试事件时，上述准确率目标分别至少需要净多正确 3 例和 2 例。报告正确例数/总例数和百分点，不只报相对百分比。

若开发集显示准确率已接近上限，可在测试前一次性改为**效率目标**：

```text
D 的 Acc@1 不低于 C，且平均累计模型 token 至少减少 25%。
底层访问量/处理量没有显著增加；具体允许幅度在测试前配置，不能事后定义。
语义错误断言不恶化，回答覆盖率一并报告。
```

测试后不能从两种目标里挑更好看的那个声称预设目标达成。小样本的“未降低”是观察结果，不自动构成统计非劣性证明。

准确率差值按独立事故组做配对 bootstrap 区间；无需引入新统计服务。多个窗口先归并为事故组，重复运行不扩充分母。样本很少或区间跨零，只称探索性趋势；不为了获得显著性无限补采。

### 11.4 效果归因与终态

| 实际结果 | 允许结论 |
|---|---|
| 语义工具各组优于 A，但 D 不优于 C | 表示/工具增益；策略额外收益尚未证明 |
| D 在更高实际成本下优于 C | 有定位—成本权衡，不称免费提升 |
| D 在相近成本下优于 C | 对比式决策出现额外质量收益；显著性另看区间 |
| D 质量相近但成本较低 | 出现效率收益；不声称诊断精度提升 |
| 无收益或退化 | 负结果；定位主要失败原因，正常结束本轮 |

最终报告用三个简单字段即可，不新增 Product 状态机：

```text
implementation: ready | partial
experiment: complete | partial | not_run
effect: quality_gain | efficiency_gain | representation_only | mixed | no_gain | undetermined
```

若效果达到预设点估计目标，仍需按样本量和区间限定结论。`experiment=complete, effect=no_gain` 可以是本 Goal 的完整研究交付；`experiment=partial` 不伪装完整验收。

### 11.5 三个案例讲解

尽量提供三个真实、有代表性的案例：操作分层改变归因、依赖对比缩小目标、证据不足而合理停下。没有某类真实案例则明确说明，不伪造凑数。

每案只回答：基线哪里不够、选择了什么分析、哪个实际观测改变判断、最终仍有什么限制。选例不取代完整测试结果，不只挑成功例子。

建议约 8–12 个聚焦测试覆盖下列问题，允许合理参数化；数量不是指标，不为数字拆测试：

正常已有 CI 不删除、不弱化、不屏蔽失败。没有发布授权时不触发远程发布流程；已有规则要求的检查正常遵守。不把每次 prompt 微调与全仓库重跑绑定，不因无关历史失败重启基础设施项目。

不要新增历史证据 verifier、通用权限定理、复杂 hash 继承链或独立审查流水线。复现只需本轮输入清单、配置、代码版本、来源引用和真实输出；必要的现有完整性检查复用一次。

## 13. 分阶段执行与停止条件

### 阶段 P0：可用性与实验定义

建立一份输入清单、数据 split 草案、工具字段支持表。确认已有 Provider 能否在授权内使用，做极小 smoke 时也计入预算。

完成标准：知道每类数据支持哪些工具、能做哪类评分；有明确的数据不足分支。不要在此阶段反复写规划代替实现。

### 阶段 P1：纯计算工具与固定流程 B

抽取可复用计算，适配现有回放，完成三个工具及固定流程。优先在开发样例上真实跑出结果，不先建平台。

完成标准：可计算样例返回实际数值与限制，关键算术正确；不能只有接口壳或全 UNKNOWN。

### 阶段 P2：C 与 D 的模型调查

新增研究任务提示、可观察预测与选择评分，接真实 Provider 完成小规模开发循环。使用相同工具和结果格式，保留普通 ReAct 强基线。

完成标准：能够观察模型真实选择分析并根据返回值更新；记录失败及成本。最多两轮开发语义修订后固定。

### 阶段 P3：四组实验与报告

先保存固定配置/划分/主目标，再配对执行 A/B/C/D；预算允许再重复 C/D。评分、配对差异、误差分析与三个案例汇总在同一报告。

完成标准：按第 11 节分别标注实现、实验和效果。收益不足不续开“补验收”任务，不自动加样本、换模型、换目标或启动 live。

### 全局停止/降级规则

安全、秘密或数据授权问题立即停止相关动作；其他无关离线工作可以继续。费用/请求/下载上限到达即停止对应外部动作，保留部分结果。

缺字段先局部降级；缺原始输入不能伪造；大的基础设施缺陷记录并绕开不相关模块。只修直接妨碍当前研究的窄缺陷。

不得通过扩大部署、采集、健康资格或正式知识治理来挽救本轮指标。不要因“效果还不够好”无期限运行。

## 15. 防止任务再次失焦

下面这些行为视为偏离 Goal，应停止并回到算法与实验：

- 因为某份旧数据的基线不足，再启动完整 Docker/健康验收链。
- 不断添加新状态、凭证、摘要证明或批准文件，但 C/D 仍没有真实模型对照。
- 模型输出 schema 合法，就宣称学会定位；仅删除原有异常就宣称改善。
- 只比较弱的旧投影与新方法，不做同工具 C/D 对照。
- 只保留模型跑对的案例，或将相邻窗口/重复调用计作独立事件。
- 为等到正结果而继续调测试集、换模型、修改主指标或消耗更多预算。
- 没有实验收益就主动扩展到聚类、RAG、RL 或知识晋升。

**最终优先交付一份可以复现、可以解释差异、敢于保留负结果的小规模算法实验，而不是一套越来越完整但仍无法说明算法增益的系统。**
