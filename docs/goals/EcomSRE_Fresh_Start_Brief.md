## 修复要求

1. 将末样本年龄、相邻间隔、窗口左边界、最低样本与查询内窗支持拆开。逐指标核对配置、固定版本默认与实际观测，观测周期不等于声明配置。参数依据生产者、指标类型、查询需求制定，与候选匹配无关。正常60秒不能仅因统一30秒被判断流；业务需求更快时报告能力不足，不一律放宽。
2. 核对晚出现序列标签、实例、首末样本、counter/reset、histogram桶组和相关span/log。分别解释已建立序列中断、新标签、服务启动不足与未知缺失。不得自动判丢失或合法出生，不补出生前零；合法出生也不保证 rate/统计或完整负例。未保留OTLP起始时间必须明确不可用。
3. 校准显示有效支持区间、最近故障/恢复/Changes、实际序列与输入；配置恢复不等于健康。保留Core优先级与业务查询；不顺便重建Docker调度。安全、权限、秘密、资源归属问题停止相关操作，普通独立检查的证据不足不永久停止整个开发任务。
4. 复用现有实现，工程校准与正式验证分开。工程数据全部是已见开发数据，每次保留参数、版本、原始结果与失败；获授权资源/预算内可修复后重试。正式验证才固定候选、协议、资格和未见事件；正式数据暴露后不调候选重报同批。工程成功不触发晋升或正式PASS。
