## 3. 修复一：参考选择必须匹配“测量的是什么”

### 3.1 统一选择函数

为 `compare_baseline` 与 `compare_dependencies` 复用一个小函数，按以下语义选择参考：

```text
服务 + 操作范围 + span方向/类型
+ signal / value_semantics + unit + statistic/method
+ 当前与参考窗口的可比定义 + 事前时间约束
```

具体要求：

1. 不再只按 scope 取字典序第一项。先筛选真正兼容的参考，再按预先固定的时间优先规则选择；同优先级不明确时报告歧义，不按“更正常”或更利于命中选择。
2. 新参考显式记录 signal 或等价的测量语义。两个值都是 fraction，不表示二者可混用：错误标记占比与显式状态条件比例必须区分。
3. 旧参考无 signal 时，只可按旧适配器已知、可核实的定义做明确兼容；不能凭相同单位猜测含义。
4. 检查实际参与计算的全部 `source_windows`，不能只检查代表性的最后一个 window。参考只用当前事件窗口之前的相应数据。
5. 依赖工具只改变观察范围，不改变正在比较的 signal；邻居参考选择遵循同样规则。
6. 不兼容、真正缺失和样本不足分别返回原因。修复不能保证所有参考都可算，也不能假造健康基线。

### 3.2 必须通过的最小算例

同一 scope 同时存在 duration_ms 与 error_fraction 参考：请求后者必须选择后者；把字典插入顺序和参考名称顺序交换，仍保持正确选择。请求前者亦然。

同单位但 signal 不同、参考晚于当前窗口、操作/方向不匹配时仍不能比较。用实际开发材料报告“原来误选、现在正确匹配”的数量；若实际材料没有该触发路径，诚实注明只完成了源码缺陷复现与修复。

## 4. 修复二：Trace 状态保真，而不是简单把 UNSET 改成健康

### 4.1 保留原始状态

新增或保留以下等价信息，不强制同名字段：

```text
raw_status_code
normalized_status: UNSET | OK | ERROR | MISSING_OR_INVALID
status_normalization_basis
```

按实际数据 schema 核实编码；该数据采用的0/1/2映射需与来源一致。明确编码的 UNSET 是一个有效值，不能因数值0是假值而当缺失；缺列、空值、无法识别的编码也不能自动套成 UNSET。原始字段未保留且不可恢复时保持不可恢复。

OpenTelemetry 将 UNSET 定义为默认状态，通常不要求正常埋点显式写 OK。[S7] 这支持保留 UNSET，不支持把整个请求链或业务结果自动标成成功。

### 4.2 统计量分开命名

对去重后的同一采样总体计算：

```text
n_total   = 当前分析范围内的采样span数
n_valid   = n_unset + n_ok + n_error
status_coverage = n_valid / n_total                 # 分母为0则null
error_marker_fraction = n_error / n_valid          # 分母为0则null
explicit_status_error_fraction = n_error/(n_ok+n_error)  # 分母为0则null
```

同时返回 n_unset、n_ok、n_error、n_missing_or_invalid、span数与唯一Trace数。新默认分析使用 `error_marker_fraction` 的确切语义；旧 `error_fraction` 不静默改名换义，明确其版本/映射。

`error_marker_fraction` 只回答“这些具有有效状态的采样span中，多少显式标记ERROR”，不是全体请求失败率、成功率或故障不存在概率。缺失比例与采样范围始终可见。

### 4.3 必须通过的语义算例

| 人工算例，仅用于验证定义 | 新输出 | 不允许推出 |
|---|---|---|
| 99 UNSET + 1 ERROR | marker=1%，explicit=100%，coverage=100% | 99个业务请求成功；原系统错误率下降99个百分点 |
| 100 UNSET | marker=0，explicit=null，coverage=100% | 根因被排除、服务健康 |
| 100真正缺失 | marker=null，coverage=0 | 零错误 |
| UNSET/OK/ERROR/缺失混合 | 每类计数和两个分母可重算 | 把缺失填零或忽略其存在 |

这些是设计算例，不是当前数据的实测分布。

依赖分析可改为报告“已采样共享Trace是否出现双方ERROR标记”，但不得继续将“未出现标记”描述为双方成功。遇到缺失、截断或不完整共享Trace，按实际声明范围保留限制；不强求所有问题得到YES/NO。

不得用放宽健康定义来降低 UNKNOWN。**观测统计可以明确，业务解释仍然可以未知。**

## 5. 算法主体：同操作、同方向的历史变化视图

### 5.1 范围键与参考构建

在现有三个语义工具内扩展，不增加工具种类：

```text
scope_key = (service, operation, span_kind/direction)
```

操作键来自真实身份与字段；不把完整分组键误当 operation，也不按错误率给操作命名。原用途映射可以保留，未匹配项仍为 UNCLASSIFIED。控制流、健康检查、内部操作与业务操作可以分别比较，但不能为降低异常量而删除其中任何一类。

使用与当前数据口径一致的已有三个历史窗口，分别计算各 scope 的参考统计。当前与参考使用同样的状态表示、单位、去重和采样方法。服务级参考保留给降级路径，但必须标注 scope 变粗，不能冒充操作级结果。

“事前历史参考”不等于“已确认健康”；不为建立参考重新启动健康资格或长周期采集。

### 5.2 返回连续变化，不把50ms门槛换成另一个万能门槛

每个 scope 返回一张紧凑特征表：

```text
当前/参考窗口、样本量与唯一Trace数
状态四类计数、ERROR标记占比及缺失比例
当前中位时延、各参考窗口中位时延、参考中心
中位时延绝对变化、相对变化（分母为0时null）
样本足够时的当前/参考尾部分位数及其同口径变化
参考波动与稳健偏离量（满足条件时）
真实来源引用、口径、采样和可计算性限制
```

默认参考中心为各可用历史窗口中位时延的中位数，明确这是“窗口统计的中心”，不是把所有历史span合并后的中位数。两种方法都使用同一权重定义，不能随事件切换。

稳健偏离量可以沿用：

```text
z = (current_window_stat - median(reference_window_stats)) / (1.4826 * MAD)
```

MAD=0时不制造巨大z，保留绝对/相对变化和零尺度说明。单位已转换且受测量精度支持时才计算，不能靠一个吞没亚毫秒变化的大epsilon掩盖问题。

建议首版配置：比较中位数时当前及每个参考窗口至少5个有效时延span，至少2个可比参考窗口；稳健z至少3个可比参考窗口且MAD>0；尾部统计每个参与窗口至少40个有效span。**这些只是开发支持阈值，不是统计充分性保证。**不足时仍返回描述性计数与明确缺口，不把低支持结果当可靠排序。付费配对前固定配置，不按根因标签调值。

尾部统计统一采用明确的样本分位数方法；单个尾部变化不是总体SLO证明。不平均操作组p95，不用“总p95−控制流p95”计算业务p95。若报告同一操作前后的p95之差，明确它仅是两个同口径分位数的描述性差值，不是分解或因果贡献。

不把按请求排列的连续高时延span数量写成连续时间或故障持续时长；本轮不新增时序SLO模型。

### 5.3 让现有工具输出新信息

- `profile_operations`：保留当前操作画像，增加状态保真统计；返回操作键与可用参考句柄。
- `compare_baseline`：允许模型选择实际存在的操作/方向参考；主要返回连续变化，不只返回固定阈值的YES/NO。
- `compare_dependencies`：使用修正后的参考选择，保留实际调用边、双方各自的变化与状态分布，不把错误共现当唯一有用关系。

C 不要求预先提供相反预测。问题说明可以是“检查该操作相对历史的变化”，不要求为了通过应用协议而将开放分析硬压成二元测试。

需要裁剪结果时保留其他组的计数、缺口和可展开句柄；选择规则提前固定，不根据真根因、模型答对与否或最终标签裁剪。若利用观测值挑选显著变化操作，必须作为已执行分析计入数据/计算成本，不能冒充免费元数据。

## 6. 采样可用性：避免模型分析的只是健康检查样本

优先恢复与旧快照**相同span身份集合**的 raw status 和操作参考，使表示变化与采样变化分离。不能通过换一批更容易答对的样本证明新表示有效。

对四个开发事件，各做一次有界的本地流式检查：对比原始当前/参考窗口与现有样本的操作覆盖、状态构成、时延统计和缺父关系。只输出必要汇总，不把整份原始遥测发送模型，不重建遥测平台。

现有450 span/窗是采样上限，不是必须达到的样本量或“完整Trace”的证明。按结束时间分窗后的Trace仍可能缺父span，不能因采样器按trace ID选取就声称全链路完整。

若原始窗口有关键类型而样本缺失，先明确“采样损失”；若原始材料也没有，则明确“源数据不足”。两者都不能靠模型补全。

**默认本轮保持采样不变。**确有覆盖缺陷直接使操作级比较无法实施时，允许在付费前进行至多一次、对两种C完全相同的采样修订：保持原450 span/窗上限，使用服务/操作/方向分层加固定哈希等不看标签、不看错误值、不看时延极值的选择规则。记录修订和未覆盖范围；不得挑选高错误/慢请求后仍将其当总体随机样本。

完整窗口汇总仅用于离线可用性诊断，不免费送给任何一组模型。修订采样后的结果不能直接与旧历史准确率作单因素比较；主要对照始终用同一份新冻结输入。

若仍缺少任何真实、可比较的操作参考，交付修复和具体数据限制，不把全UNKNOWN的模型运行当必要验收项目。不要自动采集、下载或切换数据集来挽救指标。

## 7. 顺手完成的接口修正：只减少非法表达空间

接口修正对本轮两种C完全一致，不作为其间的实验变量。

1. **动态合法值**：target与ranked_components来自全部真实候选服务；问题/参考来自当前已声明的合法句柄；证据槽只允许实际存在的E/O类结果引用。不要让模型重新拼接服务、操作和窗口。保持对真实语义关系的检查，合法枚举不等于证据支持结论。[S8]
2. **可执行目录与历史结果分离**：执行完的规范化动作不再列为可执行选项，历史结果仍可阅读和引用。动作去重不等于不同操作/信号的分析被错误合并；原末端去重保留为保护。
3. **报告结构分离**：强制报告阶段只返回报告，不再同时提交hypothesis_updates或expectations。正常主动结束也使用清楚的报告分支；仍允许有边界的拒答，不能靠一律拒答提高完成率。
4. **拒绝反馈可操作**：原子拒绝时说明哪些增量未被接受、当前真实假设ID是什么。不能暗中登记其中一部分，不能让模型以为被拒的H1已经存在。
5. **空集合正常结束**：没有可执行问题/证据时，用受支持的报告或空数组结构表示，不发送非法的空enum，不为让schema合法发明句柄。

兼容现有Provider与strict输出，不换API框架；按实际支持的schema子集实现动态约束，不使用未支持的if/then来堆复杂契约。最终解析、目标/引用和只读边界仍检查。原始错误不通过裁剪JSON、替换假引用或拼造字段“修成成功”。

暂停D/D-lite的执行与改造。不要顺便实现候选排序、调整D分数、增加多智能体或重新跑C/D。

## 8. 实验：一个零模型基线，两种正确的C视图

### 8.1 三个方法

| 方法 | 输入与行为 | 回答的问题 |
|---|---|---|
| `alert_only` | 只读取原始可见告警文本和同一候选服务表，确定性抽取服务并排序，0模型调用 | LLM/工具是否只是复述告警？ |
| `C-service` | 修正状态和参考bug后的普通ReAct；保留当前操作画像，历史对比仍为服务级 | 正确实现的服务级强基线 |
| `C-operation` | 同一个ReAct、状态/接口修复与数据；增加匹配操作/方向的历史变化视图及局部依赖变化 | 更细粒度的参考表示是否提供额外信息？ |

不能故意让C-service继续使用错误参考或混淆UNSET的旧数据。旧代码可在离线算例中复现缺陷，但不能作为唯一弱基线证明“算法创新”。

两种C使用同一原始快照、采样、候选服务、模型、推理档位、接口修复和评分。两种视图的差别是有意考察的历史信息组织粒度，不是额外采集或额外真值。当前操作画像、必要字段和参考可用性信息不得只给新方法。

若保留底层记录读取/展开能力，应两组一致。新增操作级预处理、显示排序和复合工具访问计入实际成本；不能把新视图的计算免费，而让对照付全部读取成本。

### 8.2 告警基线定义

只从原始告警文本匹配候选服务，采用明确的实体边界和最长匹配，避免cart等短词误匹配；按文本首次出现排序，完全同位按固定字典序。无匹配则空排名，不调用模型猜测、不读取答案补齐。

根因标签仅由评分器读取。多服务告警不人工挑出正确项；沿用共同服务粒度、去重与最多4个候选规则。报告该基线的定位与覆盖率，不把告警中出现服务当数据泄漏，也不假定它一定是根因。

### 8.3 固定开发批次

- 先完成纯计算和协议算例。最多2条真实开发smoke用于确认已有数据与wire，不用于挑选获胜配置；全部计费并标为开发。
- smoke后至多一次有界提示/接口修订；免费编译、路径和算术修复可以在固定批次前正常完成，不必每次另发Goal。不得修改数据来迎合标签。
- 然后固定本轮配置、样本、动作预算和报告协议。执行四事件 × 两种C × 两次重复，共16条轨迹；告警基线每事件计算一次。
- 按事件成对运行，第二次重复交替方法先后。不同方法/重复用独立run ID，不能读取旧session的完成报告。
- 每轨迹沿用最多8模型请求、6分析动作、1次格式修复（包含在8次内），输入/输出上限与底层访问限制两组一致。先核对现有有效配置，默认沿用同一模型、low/strict/4096，不自动换档位或模型。
- 16条固定批次启动后不再调参；出错保留并分类，不能悄悄重跑失败轨迹再选成功结果。不为了正结果增加重复数。

这只是四个已见事件的开发实验。两次重复各自报告，汇总时独立事件仍为4，不以16条轨迹当16个独立事件。不启动旧24例或新的未见事件测试。

## 9. 验收重点：正确性、信息增量、模型使用与实际收益分别回答

### 9.1 必须完成的交付

| 交付维度 | 具体要求 |
|---|---|
| 参考修复 | 多signal同scope算例正确；错单位、错语义和事后参考仍拒绝；明确真实数据触发情况 |
| 状态表示 | 原始状态可追溯，UNSET与缺失分开；计数和两个分母可重算；不推断业务健康 |
| 操作变化 | 实际开发材料上计算匹配的操作特征；没有的字段明确缺失，不只交接口壳 |
| 接口 | 合法目标/结果句柄可执行、报告不被无关更新拖垮、重复动作不再是正常选择项；非法引用仍拒绝 |
| 开发对照 | 有数据和授权时完成16条真实轨迹与告警基线；未启动、失败和拒答分别报告 |
| 归因 | 区分修复正确性、接口可靠性、操作表示收益与告警复述；不声称本轮验证了D |

### 9.2 离线计算表必须回答的问题

对每个开发事件，先计算并保存特征表，再由评分/人工分析与标签对照；标签不能反向参与特征或采样选择。

1. 旧UNKNOWN中，哪些来自表示混淆或参考误选，哪些是真实缺数据？
2. 操作级变化与服务级统计有何不同？有没有被服务聚合掩盖的操作？
3. 看见的变化是否只属于健康检查/控制流样本，还是有对应的业务操作信息？
4. 哪些候选确有不同的观测特征，哪些在当前材料下仍不可区分？

不要求每个事件都有强信号。任何“有判别力”的描述都必须指向实际数值、范围与来源；看起来合理的LLM解释不是该判断的唯一依据。

### 9.3 模型结果表

至少报告：

```text
方法、独立事件数、计划/启动/完成/未启动轨迹数
正确数/已启动数、Acc@1、MRR
合法拒答、非拒答覆盖、应用协议/Provider/工具失败
总模型token与费用（含失败和reasoning可见口径）
底层读取/预处理/分析成本，哪些是代理计数而非实测I/O
C-operation 对 C-service 的逐事件配对变化
两种C 对 alert_only 的纠正、维持和错误偏移
```

失败仍在已启动评分分母；未启动不是答错，但实验必须标partial。不能只在成功出报告子集上比较准确率。

至少检查有代表性的轨迹：是否引用了新操作级观测、它是否改变了候选排序或有依据地缩小歧义、还是仍只依据初始告警。若没有这样的真实案例，就明确没有，不凑数、不自动追加模型实验。

### 9.4 完成与效果不绑定

- 修复和真实计算完成，只能证明实现正确性与信息恢复。
- 两种C都比旧历史结果好，但二者相近：不能把接口/通用修复收益归给操作级表示。
- C-operation在固定开发配对中更好，且轨迹确实使用新信息：称为**开发集上的表示收益线索**，不是跨事件泛化证明。
- 模型没有超过alert_only：报告额外解释/观测是否有用，但不能宣称已经带来定位增益。
- 没有收益、退化或源数据无信号：如实收口，不恢复D来补指标。

4个独立事件不足以支持显著性或稳定泛化结论。本轮不要求bootstrap、p值或强制准确率提升门槛；正确数、重复差异和逐事件对照优先。若写百分比，必须同时给分母，不将重复当独立样本。

沿用三个简短结果字段即可：

```text
implementation: ready | partial
experiment: complete_development | partial | not_run
effect: development_signal | no_gain | mixed | undetermined
```

完整完成预定开发实验且无收益，可以正常完成Goal。数据确实不足时允许部分交付，但必须给出具体缺失字段/窗口及已完成的计算，不能只写“还要更多验证”。不修改旧阶段的effect或准确率。

## 10. 检查规模与费用：不再次演变为验证项目

约8–12个聚焦测试或参数化算例足够覆盖：状态映射/分母、真实缺失、重复span、多signal参考选择、source_windows时间/口径、操作级统计与低样本、动态句柄、报告分离、去重和单条fake Provider循环。数量不是目标，不为凑数拆测试。

每个新计算分支需有一个可手算的例子；保留真实输入上的少量计算对照。开发时仅运行相关测试和改动文件检查；已有CI要求不删、不屏蔽，不将每次提示修改与全仓库重跑绑定。

**不新增历史verifier、摘要继承链、独立审查流水线、权限定理、证书、采集资格或多套验收报告。**本轮输入清单、配置、实际版本、真实运行输出和引用足以复现；必要的既有完整性检查复用，不以反复全量哈希作为进展。

检查点公开摘要记录累计529次请求、USD6.185609，余量1071次/USD13.814391。[S6] 这仅是核对起点，运行前读取实际共用账本，不能凭文档重置或忽略其他已消费额度。

本次子上限为USD3/160次，与原累计USD20/1600同时约束。最多2条smoke和16条固定轨迹，在每条8次上限下最多144次调用；修复请求包含在轨迹上限中，不另起无限重试。若费用先耗尽则按预先确定的配对顺序保留实际结果并停止。

按每次调用的可靠上界预留，结算全部失败和未知用量；批次成本先估算但不承诺必须用完余额。不复制预算系统、不另起账本规避旧约束。本轮不自动申请新费用。

## 11. 执行顺序与明确停止条件

### P0：一次确认

确认实际HEAD、worktree、无关改动、4个开发输入及原始字段可恢复性、有效配置和剩余额度。更新唯一任务指针即可，不重审旧47个提交、不要求先补齐审阅包。

### P1：共同修复与真实数据表

先完成参考选择和状态保真，重建新快照/参考；用人工算例和真实开发输入核对。输出采样与信息可用性表，原始标签只进入独立评分。

若原始字段不可恢复，则在可做部分上交付并指出缺口，不假装完成状态修复；其他不依赖该字段的计算继续。

### P2：操作视图与接口

完成操作级参考、连续变化和必要局部依赖输出；同步落实动态合法值、报告结构与可执行目录。C-service/C-operation共用这些接口修正。

有条件时执行最多2条开发smoke，必要修复在固定配对前一次收敛。不要将每个小编译错误升级为需要用户另发Goal。

### P3：一次固定开发配对

固定配置后运行16条轨迹与告警基线。代码缺陷导致实验无法公平解释时保留失败、标清影响，不在相同批次中修完补跑并覆盖历史；可继续完成不受影响的离线分析，但不自动开启第二批。

### P4：一次收口

同一报告给出代码改动、信息恢复、实际对照、成本和失败原因。只提出一个下一步取舍：保留当前C、继续改表示、需要不同观测材料，或准备未来未见事件评估；不自动执行后续任务。

未出现收益不是延长Goal的理由。发现与本轮无关的工程缺陷记录位置即可，不扩展修复范围。涉及秘密/权限、费用到限时停止对应动作，保留可交付的离线结果。

## 12. 最小交付与报告格式

交付现有模块的窄改动、一份新实验配置、新派生快照的本地清单、真实特征与逐运行结果、聚焦测试和同一阶段报告。不提交密钥、绝对私有路径、完整原始Parquet或大型数据。

复用现有评测CLI，新增参数时只增加视图选择和本轮批次所必需的选项。报告给出**实际已运行**的输入检查、离线特征计算、告警基线和配对评测命令；不把设计中的示意命令写成已经可执行。

建议阶段章节结构：

```text
1. 起始/最终提交与实际范围
2. 缺陷如何修复；哪些只是正确性/接口修正
3. 状态、参考、操作特征和采样的真实变化
4. 数据、开发曝光与固定实验定义
5. alert_only / C-service / C-operation 结果与成本
6. 逐事件配对差异、真实信息使用与失败
7. implementation / experiment / effect
8. 允许的项目表述与一个下一步判断
```

**本轮最有价值的成果是：解释“旧表示为什么无法区分问题，新表示实际恢复了什么信息，普通ReAct是否利用了它”。不是把D的所有记录变绿，也不是给项目换一个听起来更复杂的算法名。**
