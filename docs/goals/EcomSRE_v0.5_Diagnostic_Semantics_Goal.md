## 3. 一个入口、三个固定对照

在执行结果比较前保存本阶段的实验映射与 A/B/C 定义。映射依据实际操作语义、版本和标签，不依据某标签的错误率、是否能让诊断变绿或旧候选是否命中。数据已见，不能宣称这次是预注册盲测。

| 组别 | 指标视图 | Trace 范围 | 回答的问题 |
|---|---|---|---|
| A：原始路径 | 原混合指标和原绑定基线 | 原诊断实际读到的 Trace | 能否复现历史诊断与谓词？ |
| B：语义分层 | 业务处理、控制流、未分类分别报告；可计算时一致变换基线 | 与 A 相同 | 混合统计造成了哪些解释变化？ |
| C：分层＋跨窗口关联 | 与 B 完全相同 | 仅增加本次已经保留、与窗口相关的长 RPC 上下文 | 对异常的解释与定位歧义多提供了什么证据？ |

A→B 只改变指标用途分层；B→C 只改变 Trace 关联。不得同时调整阈值、服务集合、内存信号、Core 优先级或固定学习规则。

三组均在**离线实验视图**中运行，不能改写原诊断、伪装成当时的正常入口结果或注册新的知识。控制流与未分类信号不会因不进入某项业务指标而消失。

## 4. Phase A：先复现原结果，再实施对照

### A1. 原始路径复现

复用现有连接器解析、行动顺序、基线 profile、memory 构造和诊断/资格纯函数。需要 app/repository 时使用临时库或只读适配，不运行真实 Worker 外部读取。

两个窗口至少重现：

- 连接器归约数值和有限点/NaN 数量；保持原逻辑，记录而非静默修补。
- 原 `memory_sha256`、已成立谓词、已知规则匹配、健康拒绝原因。
- `OPEN_WORLD_ROOT_AMBIGUOUS` 与 `ABSTAIN` 的决策依据。没有可直接调用的纯函数时，复用 bridge 所用原组件，不另写一套“预期答案”规则。

找不到原片段或输入摘要不一致时，指出确切缺口。先完成其他可独立验证的工作；不得把不同版本/部署的响应拼成 A 的成功复现。

### A2. 数据可计算性清单

分别核实基线与检查窗口是否都有**同粒度标签和原始序列**。原混合统计不能反推唯一的业务子集基线。

每一格标明：`EXACT_REPLAY`、`LIMITED_NUMERIC_RECONSTRUCTION`、`DIAGNOSTIC_PROXY_ONLY` 或 `NOT_COMPUTABLE`。这些只是实验输出字段，不是新的 Product 协议。

材料不足时允许输出局部对照，但必须真正计算可计算部分、完成该分支的反例测试，不能用三组全填 UNKNOWN 代替实现。

## 5. Phase B：分开指标用途，不隐藏不利信号

### B1. 最小操作语义映射

按可用的 service、完整操作名、span kind、RPC 方法/系统及实际代码语义，划分：

- `BUSINESS_REQUEST`：同步业务请求。
- `BUSINESS_ASYNC`：业务消息消费/异步处理，包含适用的风控消费路径。
- `CONTROL_STREAM`：有依据的控制流或长连接操作，例如本次已识别的 flagd EventStream。
- `UNCLASSIFIED`：不足以确定用途的操作。

不能用“所有 SERVER 才是业务”把异步风控排除；不能只按 ERROR 状态分类；不能把名字包含 EventStream 的任意操作都无条件豁免。状态是结果，不是用途。分类缺字段时保留未分类，不按好坏推断。

把分类表和理由保存在一份实验配置中，报告包含所有排除出业务统计的操作及其计数。相同操作的成功/失败必须落入同一用途组。

### B2. 数值口径保持一致

- 对每个用途组，错误分子、请求分母、请求支持和 latency histogram 使用同一总体和方向定义；同一 RPC 的 client/server 两侧不得默认为独立业务请求。
- 保留全部控制流指标：超时、持续时间、请求量以及现有证据能支持的重连信息。未知影响不能写成无害。
- 基线有原始子集序列时按同一映射重算；只有混合基线时标为 `BASELINE_SCOPE_UNAVAILABLE`，不能套用旧混合基线得出新健康结论，也不能使用检查窗口训练自己的基线。
- 资源内存、CPU、Runtime、queue 和 Changes 不随 RPC 分层而删除。内存增长保持独立问题，gauge 下降不当成 counter reset。
- 零流量、缺失、NaN、截断、新标签和已证实的零错误分别处理；不补造出生前零，不只比较有利的有限点。

### B3. 离线算术的边界

先复用已有逐时点贡献分析和已保留查询结果，不建设通用 PromQL 引擎。

1. 原组 A 必须与保存的响应核对。分组后的 counter 增量分析可以是解释性 proxy，但不能自动等同于 Prometheus `rate()`。
2. 只有所需原始样本、reset/边界语义和限定算子行为可验证时，才做数值重建；优先复用已有实现。必要的小型辅助函数限于现有表达式子集，并用固定版本参考及数值反例校验。未知语法/不支持情况明确拒绝，不扩大成解析平台。
3. `rate` 的边界外推、先按序列计算再聚合及不同采样网格需明确处理；未对齐 raw delta 不能冒充完整请求率。[R4]
4. p95 不能通过“总 p95 − EventStream p95”求得，也不能平均各组 p95。需使用该组完整的累计桶、时间点和经过验证的桶率求分位；做不到则只报告桶增量归属、样本支持和缺口，不输出虚构业务 p95。[R4]
5. 从 counter 变化推导的概率/比例和原窗口有限时点均值分别命名；不能混称为真实用户订单失败率。

**重要停止线：**缺少精确数值计算能力时，保留定量 proxy 和局部结论即可；不得为让 B 完整出诊断而开发另一套查询引擎或重新采集。指标按用途拆分后的绝对值可报告，但没有同语义基线时不宣称异常已经消失。

## 6. Phase C：关联已有跨窗口 Trace，不宣称获得因果真相

### C1. 构造一个窄范围关联函数

只读取已经保存的正常 Trace 和扩展生命周期上下文。按 `(trace_id, span_id)` 去重；client/server 是两个真实 span，但没有关系证据时不能把它们当成两个独立故障或强行拼成一条 RPC。

保留并区分：

- span 的原始开始时间、结束时间、duration、服务/实例、parent/link、RPC 方法和状态；缺字段保持缺失。
- 诊断观察窗口，以及其中每个 `rate` 的实际支持区间。
- Trace 请求范围、响应/捕获时间、截断和最大返回数。

匹配分类至少包括 `START_IN_WINDOW`、`END_IN_SUPPORT_WINDOW`、`OVERLAPS_WINDOW`；输出关联类型，而不是把 span.startTime 修改到窗口内。对指标增量解释，主要核对 span 完成时点与相关 counter 增量区间，再验证服务/实例/操作关系；仅时间接近不升级为唯一归因。

流式 RPC 的 span 可以覆盖整条流的生命周期。[R5] 因此须分别报告“span 没进入原起始时间检索”“span 后来才被采到”“有界响应被截断”等状态；不能统一写成“原系统没读全”。

### C2. 保留在线可用性边界

扩展上下文可能在原诊断之后捕获。C 默认标为 `POST_HOC_AUGMENTED`，不能声称在线同预算可获得。

只有返回时间、span结束时间和实例证据都满足原截止点，才能注明该条具备当时可用的证据；否则 `ONLINE_AVAILABILITY_UNPROVEN`。不能因为事后找到 span，就认定当时的 LLM 只需多读一次就一定能正确定位。

报告原输入、额外输入的唯一 span 数与捕获范围；零新增网络请求不等于零额外证据成本，不计算“在线工具效率提高”。

### C3. 进入现有诊断组件或保留旁路解释

尽可能通过原 Trace 归一化和现有推断组件比较 C 与 B。若原契约合法地不接受跨窗 span，只在**实验适配层**传入带真实窗口的上下文，不放松正式连接器、不伪造原 observation/evidence ref、不硬改谓词为 TRUE。

如果这类上下文只能支持说明而不能改变当前规则输出，应如实交付：“多了关联解释，但当前判定器仍 ABSTAIN”，不能增加一条 `看见EventStream就认定flagd根因` 的获胜规则。

跨服务同步异常、共享控制流、独立业务故障及资源增长可作为**对照解释**展示。解释应有支持/冲突/未知条目，不建新的多智能体或假说平台，也不把共同依赖相关性当成根因。

## 7. 评估与必须保留的反例

### 7.1 每个真实窗口输出同一张表

| 输出维度 | 要求 |
|---|---|
| 输入范围 | 同一实例/窗口，原始与新增输入区分；B/C 的指标和基线定义一致 |
| 业务/控制流/未分类 | 样本数、请求/错误增量、可计算的指标及基线状态；未知不算零 |
| 判定 | 真实原诊断、实验判定或无法判定原因；原 predicate 集、变化集和保留的内存异常 |
| Trace 关联 | 原输入缺席、额外匹配、匹配强度、截断/未完整性及在线可用性 |
| 歧义 | 原有候选/根服务歧义是否变化；只有既有推断规则有依据地变化才计数 |
| 限制 | baseline周期不足、未知操作、缺少原始桶/样本、无法建立因果/健康结论 |

至少量化可计算的控制流贡献比例、被分组的操作数量、未分类比例、新增有依据的关联数，以及判定变化。如果某项分母不可确定，则给出范围或未知，不虚构百分比。

**本阶段不报告诊断 accuracy/F1、误报率下降或算法泛化提升**：两次已见工程窗口没有独立根因标签，调用成功也不是全系统健康真值。ABSTAIN 减少不是单独的质量指标。

### 7.2 聚焦反例

保留已有测试；新增直接对应实验逻辑的少量反例，至少覆盖：

1. EventStream 是控制流，但有真实业务请求错误时不能一并消除；只改错误分子必须失败。
2. 新操作/缺标签保持 UNCLASSIFIED；异步消费不能因非 SERVER 被全部排除。
3. 分组桶的计算不同于 p95 相减；零流量、NaN、reset、缺桶和分母缺失不会变成健康。
4. 原始与分组基线不匹配时不得输出“健康改善”；检查窗口不得给自己建基线。
5. span 开始在窗口前、结束在支持区间内；错误实例、只有时间巧合、重复 span、捕获晚于截止、截断等情况正确区分。
6. EventStream 被解释后仍保留独立内存增长；没有因果证据时仍可 ABSTAIN。
7. 默认线上分路和历史输入 A 不变；实验开关关闭时不能调用新分层或旁路规则。

fixture 的合成故障只验证代码行为，不计真实事故效果。完整离线链不跳过被比较的分类、数值计算或关联函数。

## 9. 完成条件、停止条件与下一阶段边界

### 本 Goal 完成

同时满足：

1. A 复现两个原窗口的重要数值、memory及决策，或以确切材料缺失给出逐项未复现范围；不得误用旧版本部分输入。
2. B 的操作分组和一致统计已实现，真正计算可计算部分；基线不足的健康/谓词结论被挡住。
3. C 使用已经保存的跨窗 span，给出可重放关联与比较，区分事后上下文、在线可用性与因果结论。
4. 反例测试通过，原正式查询、阈值、规则、注册与默认诊断行为未改变。
5. 运行全部可行的真实数据比较，提交一份能明确选择下一步的报告；没有再扩展 credential 或平台。

这表示“诊断语义对照阶段完成”，不表示业务健康、独立验收或 LLM 能力提升。

### 允许工程迭代

本阶段为离线开发，普通代码错误可修复重跑，不受旧正式批次的“一次失败永久停止”约束。A/B/C 实验含义不反复调到有利结果；若发现初始分类有语义错误，保留旧输出并说明修正依据。不得搜索过滤条件或 baseline 直到拿到 PASS。

关键材料缺失时，完成可行计算、实现和反例后，以局部结论结束；缺失私有输入且无法完成任何真实比较时，标为 `BLOCKED_INPUTS` 并列出所需路径/字段，不生成伪造样本冒充结果。不能为等待材料而循环创建 Goal、重复全仓检查或再设计证据框架。

### 报告最后必须作选择

只能依据本次结果提出最小下一步，不自动执行：

- 若分层语义得到数据支持、但新基线缺少代表性：提出**一次有明确周期与业务范围的工程基线观察**，列出必要信息；不恢复四事件盲测。
- 若跨窗关联有解释价值、但规则仍无法区分原因：整理真实对照案例和所缺区分信息，作为后续有界 **LLM 调查策略实验**的输入；不能把本次零模型调用写成模型推理提升。
- 若分层没有可靠收益或关键数据不足：如实保留，指出最小证据缺口；不继续扩建遥测校验器。

这三种情况均不自动授权 Provider、Docker、采集或正式注册。后续是否采用新指标定义，需要用户明确接受，并在新定义下复核已有开发数据；旧 5/5 与失败成绩不跨语义继承。
