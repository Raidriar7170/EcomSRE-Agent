# DTA v2.2.6 Interview Brief

## 30-second version

The first real-fault experiment proved safe capture and cleanup but both Agent
paths failed their output protocols, so it could not measure diagnosis quality.
I preserved that negative result, reproduced the exact Current failure on its
real bytes, replaced an over-strict metric-equality gate with a target-complete
Resource Comparison Set, and moved both arms onto one shared terminalizer.

After deterministic and real-Provider gates plus independent pre-live review, I
ran one new owned Ad CPU campaign. The same physical baseline and fault were
rendered through two opaque swapped maps and evaluated once in eight paired
arm-runs. Both arms were 4/4 protocol-valid. Runtime-guided Current was 4/4 exact
with one two-target Resources bundle per case; Model-directed retrieval chose
empty reads and then valid Abstain in all four cases, so it was 0/4 exact.
Current also used 4 versus 12 Provider calls and 2,562 versus 9,116 tokens.

The transfer terminal is
`DTA_V226_CURRENT_REAL_FAULT_TRANSFER_SUPPORTED`, with exact baseline
restoration, `CLEAN` cleanup, zero non-owned drift, and zero Agent writes,
ActionProposals, or Runbooks.

## What I would not claim

- This is not the exact frozen historical v2 Agent.
- Four opaque cases are not four independent fault episodes.
- The result does not establish statistical significance or production readiness.
- It does not test faults outside owned Ad CPU saturation.
- Model-directed's protocol validity does not make its Abstain outcomes exact.

## Useful implementation points

- Stage-specific fail-closed traces made the predecessor failure actionable.
- Resource Comparison Set asks which unresolved targets need the same evidence,
  rather than requiring unrelated bootstrap values to be identical.
- Shared terminal admission isolates evidence acquisition from Diagnosis-object
  formatting.
- Truth was unavailable during arm execution and loaded only after each pair.
- The live sequence reused the existing v2.1 ownership/fault lifecycle and put
  restoration/cleanup in `finally` before the snapshot study.
