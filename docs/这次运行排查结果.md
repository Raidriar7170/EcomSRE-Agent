## 6. 根因分析

### 6.1 直接根因：Compose observer 摘要脱敏不完整

`_persist_success_artifacts` 尝试写 observer-visible Compose 摘要时，
observer 安全检查拒绝了键：

```text
FLAGD_OFREP_PORT
```

该键命中 observer zone 对 flag/hidden-truth 语义的禁止规则。原 sanitizer
已经处理 evaluator-only 路径、control 路径和 scenario 标识，但没有处理该
键。

### 6.2 Stop gate 根因：资源标签包含 evaluator-only bind 路径

Smoke finally 尝试重新建立 fresh authority 时，preflight 的内部判定实际为
`SUCCESS`，但 observer-visible preflight 快照包含以下 Docker label value：

```text
.../artifacts/phase0/evaluator-only/<run_id>/control
```

该路径来自 flagd 和 flagd-ui 的 bind-source 标签，被 observer 安全检查
拒绝，导致 fresh preflight 无法持久化并返回
`STOP_AUTHORITY_INPUT_UNAVAILABLE`。

### 6.3 错误分类缺陷

Post-up 代码把 ownership discovery、ownership authentication 和 success
evidence persistence 放在同一个宽异常边界内。证据持久化失败因此被错误
报告成：

```text
POST_UP_OWNERSHIP_UNPROVEN
```

实际上，已保存的 ownership manifest 和 HMAC anchor 可以成功加载，
manifest 中 31 项资源与 resolved Compose 完整匹配：

- 25 containers；
- 5 port bindings；
- 1 network。

该错误分类边界尚未彻底拆分，是后续修补项。

### 6.4 Checksum sealing 缺陷

Smoke report 完成后，安全停机继续向 append-only
`commands/process-audit.jsonl` 写入命令记录。最终 checksum manifest 中该
文件的旧 hash 因而失效：

```text
expected: fbdb418fb4dd070b3a3277b7060beeb9876b7c2933a7c06b77e404f09eef14a3
actual:   b1df77d26291616c3659273ce11968b2c93319e8a97c8c1205603ae81bd1ba2f
```

1068 个 checksum 条目中有 1 项不匹配。不得把这份 checksum manifest 声明为
完整通过。
