## 6. 根因分析

### 6.1 直接根因：Compose observer 摘要脱敏不完整

`_persist_success_artifacts` 尝试写 observer-visible Compose 摘要时，
observer 安全检查拒绝了键：

```text
FLAGD_OFREP_PORT
```

该键命中 observer zone 对 flag/hidden-truth 语义的禁止规则。原 sanitizer
已经处理 evaluator-only 路径、control 路径和 scenario 标识，但没有处理该
键。

### 6.2 Stop gate 根因：资源标签包含 evaluator-only bind 路径

Smoke finally 尝试重新建立 fresh authority 时，preflight 的内部判定实际为
`SUCCESS`，但 observer-visible preflight 快照包含以下 Docker label value：

```text
.../artifacts/phase0/evaluator-only/<run_id>/control
```

该路径来自 flagd 和 flagd-ui 的 bind-source 标签，被 observer 安全检查
拒绝，导致 fresh preflight 无法持久化并返回
`STOP_AUTHORITY_INPUT_UNAVAILABLE`。

### 6.3 错误分类缺陷

Post-up 代码把 ownership discovery、ownership authentication 和 success
evidence persistence 放在同一个宽异常边界内。证据持久化失败因此被错误
报告成：

```text
POST_UP_OWNERSHIP_UNPROVEN
```

实际上，已保存的 ownership manifest 和 HMAC anchor 可以成功加载，
manifest 中 31 项资源与 resolved Compose 完整匹配：

- 25 containers；
- 5 port bindings；
- 1 network。

后续离线修补已拆分六个执行阶段，并使用四类稳定 reason code：discovery 与
resource completeness 各自独立；manifest create/verify 和 context
authentication 共享 ownership reason；evaluator 与 observer persistence
共享 persistence reason。共享 reason 的内部阶段通过诊断字段区分。该修补
尚未经过新的真实 smoke。

### 6.4 Checksum sealing 缺陷

Smoke report 完成后，安全停机继续向 append-only
`commands/process-audit.jsonl` 写入命令记录。最终 checksum manifest 中该
文件的旧 hash 因而失效：

```text
expected: fbdb418fb4dd070b3a3277b7060beeb9876b7c2933a7c06b77e404f09eef14a3
actual:   b1df77d26291616c3659273ce11968b2c93319e8a97c8c1205603ae81bd1ba2f
```

1068 个 checksum 条目中有 1 项不匹配。不得把这份 checksum manifest 声明为
完整通过。

## 7. Post-UNSAFE 离线修补

六项 Must Fix 已在离线代码和测试层闭合：

1. post-up discovery、resource completeness、ownership authentication 与
   evidence persistence 使用独立失败分类；
2. 已认证 stop authority 不再依赖 observer 证据写入成功；supervised smoke
   将写入失败记录为 `UNSAFE`，但不会取消对同一 daemon、同一精确资源集合
   的安全停止能力；
3. observer Compose evidence 改为构造式 allowlist projection，不再依赖对
   任意字段做字符串遮蔽；
4. terminal report、versioned recovery seal 与 append-only chained seal
   index 能覆盖 stop 后新增的审计记录，并保留旧 seal；
5. image-lock contract tests 使用独立的 `UNINITIALIZED` 和 `LOCKED`
   fixtures，不再读取可变的仓库状态决定预期；
6. Compose override 为三个镜像声明的数据目录提供 run-scoped、带 ownership
   labels 的 named volumes；pre-mutation 检查拒绝所有 service 中的匿名、
   未声明、未标记或目标不匹配 volume。

新增和加强的测试覆盖对应失败路径、tamper detection、daemon/resource drift
以及 observer persistence 失败后的精确停止。修补后没有执行 Docker 命令、
第二次 smoke 或正式验收，因此这里只能声明离线闭合，不能声明真实环境闭合。
